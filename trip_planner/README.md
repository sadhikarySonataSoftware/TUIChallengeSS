# Trip Planner — Flutter submission

A clean Flutter implementation of the Trip Planner challenge using **Riverpod**, **Dio**, and **flutter_map**. The cheapest-route calculation is implemented entirely in Dart; the API only supplies the graph data.

## Architecture

```text
lib/
├── core/
│   ├── config/          API configuration via --dart-define
│   ├── logging/         Application logging
│   ├── network/         Dio provider and HTTP interceptors
│   └── localization/    Localization configuration and delegates
│
├── data/
│   ├── datasources/     HTTP data source implementations
│   ├── models/          JSON serialization and domain parsing
│   └── repositories/    Repository implementations
│
├── domain/
│   ├── entities/        Framework-independent business objects
│   ├── repositories/    Repository contracts
│   └── usecases/        Dijkstra cheapest-route algorithm
│
└── presentation/
    ├── pages/           Screen composition
    ├── providers/       Riverpod state and dependency wiring
    └── widgets/         Destination carousel, city images, and route map
```

### Key decisions

- **Riverpod 3**: dependency injection + async state without coupling business logic to widgets.
- **Dio**: a small, configurable HTTP client with timeouts and interceptors.
- **flutter_map + OpenStreetMap**: pure-Flutter map rendering without requiring a Google Maps key.
- **PageView**: Flutter-native swipeable destination carousel; no carousel package is needed.
- **Dijkstra**: all prices are non-negative, so Dijkstra guarantees the minimum total price and handles direct + multi-leg routes.
- **Flexible JSON parsing**: supports the expected flat fields and several common coordinate/city aliases, making the client resilient to equivalent challenge fixtures.

## Algorithm

The route graph is directed: each connection is an edge from departure city to destination city with `price` as its weight.

Dijkstra maintains the cheapest known price for every city and a predecessor connection. Once the target is reached, predecessor edges are reconstructed in reverse order.

**Complexity:** `O((V + E) log V)` time with the binary min-heap and `O(V + E)` memory.

Because all prices are expected to be non-negative, this is preferable to Bellman-Ford. If negative prices were ever introduced, Dijkstra would no longer be valid.

## Run on macOS

This archive contains the complete Dart application, tests, API, assets, and configuration. Because Flutter's platform folders are generated by the installed Flutter SDK, run this once after extracting on your Mac if you want the standard `ios/`, `android/`, `macos/`, and `web/` folders generated locally:

```bash
cd trip_planner
./scripts/bootstrap_platforms.sh
```


### 1. Start the FastAPI server

```bash
cd api_fastapi
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --reload --port 8000
```

Swagger: http://localhost:8000/docs

### 2. Run Flutter

From `trip_planner/`:

```bash
flutter pub get
flutter run -d macos --dart-define=API_BASE_URL=http://localhost:8000
```

For iOS Simulator:

## Verbose logging

The Flutter module now has centralized verbose logging through `AppLogger` and a Dio interceptor. In debug builds, logs are enabled automatically. Logs include:

- API request URL, method, query parameters, headers and response summaries
- HTTP errors, status codes and Dio error types
- Repository/data-source loading and parsing counts
- Riverpod provider loading/failure events
- Dijkstra route-search progress, edge relaxation, visited nodes and final route legs

Logs are grouped with tags such as `TripPlanner.HTTP`, `TripPlanner.DATA`, `TripPlanner.REPOSITORY`, `TripPlanner.STATE`, and `TripPlanner.ROUTE`.

For a release/profile build where verbose logging is also required, explicitly enable it:

```bash
flutter run -d macos \
  --dart-define=API_BASE_URL=http://localhost:8000 \
  --dart-define=ENABLE_VERBOSE_LOGS=true
```

Disable it explicitly when needed:

```bash
flutter run -d macos \
  --dart-define=API_BASE_URL=http://localhost:8000 \
  --dart-define=ENABLE_VERBOSE_LOGS=false
```

The logger uses `dart:developer` rather than `print`, so messages are easy to filter in Xcode/Flutter DevTools. Response bodies are truncated to avoid flooding the console.

## HTTP / platform notes

For Android debug builds, cleartext HTTP may need to be enabled because the challenge API is local HTTP. The simplest approach is to use a debug-only Android network security configuration or the platform configuration generated by your current Flutter template. Do not enable cleartext globally for a production release.

For iOS/macOS local HTTP development, use the appropriate local-network/ATS configuration only as needed for the target platform and environment.

## What the screen does

1. Loads `/connections` and `/cities`.
2. Shows destination cards in a horizontal `PageView`.
3. Lets the user choose any departure and destination city from the graph.
4. Calculates the cheapest direct or indirect route locally.
5. Shows every ordered leg and total price.
6. Plots all leg coordinates on an interactive map.
7. Handles loading, empty, API error, retry, and no-route states.

## API response shape expected

The bundled FastAPI sample exposes a representative dataset. The Flutter parser accepts the common shape:

```json
{
  "departure": "A",
  "destination": "B",
  "price": 50,
  "departure_latitude": 12.3,
  "departure_longitude": 45.6,
  "destination_latitude": 23.4,
  "destination_longitude": 56.7
}
```

The challenge's supplied API can replace the sample data without changing the route-finding layer, as long as the endpoint contract remains compatible.

## Verbose console logging

Debug builds log by default. Logs are written with both `debugPrint` (terminal/Flutter console) and `dart:developer` (DevTools).

```bash
flutter run -d macos \
  --dart-define=API_BASE_URL=http://localhost:8000
```

For profile/release builds, explicitly enable logs:

```bash
flutter run -d macos --profile \
  --dart-define=API_BASE_URL=http://localhost:8000 \
  --dart-define=ENABLE_VERBOSE_LOGS=true
```

Log tags include `APP`, `HTTP`, `DATA`, `REPOSITORY`, `STATE`, `ROUTE`, `UI`, `IMAGE`, and `MAP`.

## City images

The `/cities` endpoint returns paths such as `/assets/cities/amsterdam.svg`. The Flutter carousel converts these to the configured API base URL and renders SVGs with `SvgPicture.network`.

Example:

```text
/assets/cities/amsterdam.svg
        ↓
http://localhost:8000/assets/cities/amsterdam.svg
        ↓
SvgPicture.network(...)
```
